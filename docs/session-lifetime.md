# 输入会话的无输出保活

**开发分支已接入动态 rendition owner，最终验收未完成。该策略仅用于显式选择 `rendition_backend: process/thread` 的新运行时；省略后端保留既有固定输出路径。接口见 [编码分支运行时](rendition-runtime.md)。**

创建任务时，在配置顶层指定 `idle_timeout_ms`，不放入各个 `outputs` 条目。省略时为 `60000` 毫秒：

```json
{
  "input": "input.ts",
  "rendition_backend": "process",
  "idle_timeout_ms": 60000,
  "outputs": [{"id": "preview", "output": "preview.ts"}]
}
```

| 值 | 删除最后一个输出后的行为 |
| --- | --- |
| `0` | 不保活，立即开始结束输入会话 |
| 正整数 | 最多保活指定毫秒数，期间允许重新添加输出 |
| 省略 | 使用 `60000`，即 60 秒 |

范围为 `0..2147483647` 毫秒；拒绝负数、浮点数、字符串、布尔值和 null。显式默认值与省略具有相同的任务配置指纹；不同时间值具有不同指纹。该值在本次会话创建后固定，不由输出覆盖。

计时由输入 pipeline owner 使用单调时钟执行，从最后一个输出正式从拓扑移除时开始。重复移除、状态查询、控制器重连以及尚在准备中的添加请求不能刷新期限。新输出必须在期限之前通过 owner 检查并实际挂接，才能取消计时；恰好到期限即视为过期。超时结束后，先前接受的候选输出也不能复活会话，需要重新创建任务。后续再次移除最后一个输出时开始一个完整的新计时区间。

这里统计拓扑中保留的逻辑输出，包括失败后等待手动恢复的输出；某个编码器失败不等于用户删除了该输出，不会触发这项删除保活计时。默认手动恢复与可配置自动重启是另一项策略，不能混用这两个时间参数。

保活期间应继续读取和解码输入，以便新输出从当前完整解码帧开始；不缓存这段时间的历史原始帧。输入 EOF、共享输入失败、任务停止和服务退出仍按正常终止流程执行，不等待保活计时结束。控制器断线本身不终止会话。

会话过期只是停止新媒体及新挂接的依据，不是共享像素可以回收的证明。删除分支仍须按 detach、有限 drain、终止、pidfd 确认持有者退出的流程清理；不能以保活计时到期替代跨进程引用的退出证明。

`tests/unit/session_config_test.c` 检查配置范围、会话作用域及指纹；`tests/unit/session_idle_test.c` 使用受控单调时间检查零保活、指定时长、精确截止边界、成功挂接取消、重复删除不续期以及 stop/EOF 的终态。`tests/integration/rendition_process_integration.py --phase lifecycle` 另外验证真实热增删、挂接取消保活、移除 drain、精确帧区间及最终槽回收；具体通过的构建以本轮验收报告为准。
