# AVC/HEVC 快出的本地稳定性改进

**实验版，最终验收未完成，不建议生产启用。**

本轮按用户指定的本机开发验收范围推进 main，保留现有默认开关；不部署，
不以远端 CI 代替本地验证。整个 Linux 服务仍属实验性服务，以下功能检查
不能代表其他硬件、并发数、生产容量或任意损坏输入已经验收。

## 实现与资格

H.264 将完整图像的显示退休状态与参考解码 DPB/MMCO 拆开。帧 setup 恢复
普通路径的放行时机；完成重建的 AVFrame 引用按输入顺序进入独立有界显示
状态，后续 worker 可继续解码。普通 DPB 仍按原规则选择，已提前显示的帧
靠不随槽位复用的 ID 去重。额外输出引用全部准备成功后才提交水位；失败
退回普通输出。flush 先停稳 worker，再清理显示状态；抑制重复不能提前结束
EOF drain。详细所有权、容量边界和证明限制见 FFmpeg 的
`doc/early-output-stability-20261022.md`。

AVC 自动快出仍要求受支持的单 slice、逐行 POC0 和有效 HRD/CFR 时序声明。
没有 HRD/CFR、普通多 slice、参数不兼容、损坏、缺口等情况安全回退。服务
不会自行声明 `live_poc_verified_even` 的外部完整输入证明。HEVC 保留既有
IDR_N_LP 锚点和连续 POC+1 的策略；不能将该规则直接套到 AVC 的合法 POC
间隔上。本轮为 HEVC 增加命中观测，未改其选择算法。

async 是有界异步前端/派发；快出是编解码器内的显示选择；decoder_pump 是
可选应用前端线程；auto 是可选动态派发控制，四者语义独立。本轮一并纳入
前一开发提交的 pump eventfd 唤醒修正，不改默认启用状态。默认仍为 async
开、auto 开、pump 关、HEVC 快出开、AVC 快出关。普通接口仍可用帧线程。

服务状态增加实际 codec 选择统计，可区分“要求开启”“有资格”“实际快出”
和回退原因。字段语义见 [decoder controls](decoder-controls-20261022.md)。
这些统计不是服务实际写出帧数，不能用来替代 trace、源 ID、显示顺序和输出
文件解码核验。状态只在 pipeline owner 取得快照后入 job 锁，不直接读 worker
可变 DPB。清理解码器前保留最终统计。

## 验收边界

本机环境是 macOS ARM 上的 Colima Ubuntu 24.04 amd64/Rosetta、8 vCPU/
12 GiB。仍需在实际原生 Linux 目标机上做多路长时间稳定性、CPU、持续吞吐、
队列增长和端到端 ingress-to-mux P95/P99 容量验收，以及独立最终复审。
该延迟终点是本地 mux/flush 完成，不是播放端画面出现。消毒器和静态复核
都不能证明无数据竞争或所有损坏码流均安全。无 HRD AVC 的普遍快出仍未知，
本实现选择回退，不能描述为常规片源普遍有效。

## 1080p 输入的 64 秒服务检查

## 最终完整 SDK 的 CPU/持续吞吐子集

以下是绑定上面最终 SDK 身份的新测量，不是提交前快照。输入为 1080p60
