# Candidate identity and separate debug files

The source commit alone cannot identify a dirty local build or two different runs of one commit. `scripts/release-manifest.py source` records the commit, dirty state, relevant tracked/untracked source hashes and native/yyjson gitlinks. Its canonical content digest is independent of file mtimes. Capture it before building; candidate creation fails if those inputs changed afterward.

The service workflow uses `naki-live-transcode:COMMIT-RUN_ID-RUN_ATTEMPT`. Runtime labels bind the commit, source-tree digest, run/attempt and SDK key. A candidate manifest requires actual Linux/amd64 image inspection, the unique tag and immutable Docker image ID; repository digests are retained when available. An image ID is not a claim that an image was pushed to a registry.

Creation verifies the SDK against the trusted checkout and selected dependency key, then checks actual application/native ELF Build IDs against separately archived DWARF hashes and Build IDs. Runtime ELF hashes describe the stripped image files, while debug hashes describe the separate debug files. The SDK's content receipt is checked after overlaying the actual image's native libraries. Image/symbol archive byte counts and SHA-256 hashes bind the transported artifacts. Verification rejects mismatched image labels, Build IDs, debug files, SDK identity or archive bytes.

`--local` permits review of actual ELF/DWARF without a Docker image; `image=null` and `publication_eligible=false` make that limitation explicit. It verifies clean pinned native histories and the actual SDK source/recipe content, but may include intentionally uncommitted application/recipe work; its `local-content-...` dependency identity is explicitly not a release tag. Release-mode creation still requires the existing clean committed SDK release-key checks. Any dirty source also makes publication eligibility false. Neither creating nor verifying a manifest publishes, pushes, tags, merges or deploys anything. A manifest binds bytes and inputs; it does not replace the candidate test matrix, actual collector acceptance or target-host soak.

`tests/release_manifest_test.py` uses real compiled ELF and extracted DWARF for positive/mismatch/corruption checks, plus source, image/run/attempt/platform and archive-byte rejection cases. The earlier local engineering window did not run Docker builds. Local validation and source review are indexed in [validation-final-review.md](validation-final-review.md); actual image/smoke and remote Actions results must be checked for the corresponding PR/commit. Actual image extraction/verification remains a separate execution gate, not a pass established by local source tests.

The application source digest reads yyjson's actual src files explicitly because a parent Git file listing stops at its gitlink. Same-mtime JSON-library changes must alter the source digest; yyjson HEAD/worktree state also contributes to dirty status. FFmpeg/VVenC source/recipe content and clean pinned histories are enforced by their separate SDK gates.
