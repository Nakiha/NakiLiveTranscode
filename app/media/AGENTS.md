# Media ownership and maintenance

Read `docs/architecture.md` for the implemented boundaries and test selection.

- Keep public headers free of `worker/job.h`, `pipeline_internal.h`, `mux_internal.h`, and `rendition_runtime_internal.h`. Use forward declarations and explicit dependencies. Private include consumers are enumerated by `scripts/check-architecture.py`.
- `Pipeline` is orchestration state, not a place to add shared component internals. New mux/audio/protocol state belongs inside `NakiMux`; no other component may define, inspect, copy or free that object. Its implementation is `pipeline_output.c`, `pipeline_mux.c`, and `pipeline_audio.c`, compiled together as `naki-media-output`.
- Input/decode state belongs to opaque `NakiInput` (`naki-media-input`); filter/compositor/encoder/ledger state belongs to opaque `NakiVideo` (`naki-media-video`). Only each component's enumerated implementations include `input_internal.h` or `video_internal.h`. Fixed branch queues/threads are private to `pipeline_branches.c`. Do not add native codec/format/stream fields back to Pipeline or include another component's private representation to avoid an API.
- Media never includes `worker/job.h`, holds a Job mutex, writes Job fields, or receives mutable progress/statistics pointers. Use immutable configuration/identity and typed publication/factory contracts. Actual completed-write publication remains mux-owned; the worker owns sampling/windows and final classification.
- Destination writers retain a reference to `NakiEncodedDescription`, sealed on the video owner after codec open, and a scalar stream timing snapshot. Never lend them the active encoder, an `AVStream *`, mutable input arrays or filter state. IDR requests and actual-write feedback use video-owner APIs on their authorized owner thread.
- `pipeline_mux_move` is an exclusive transfer between quiescent owners of the same Job. Move the same allocation; do not clone it. Prepare immutable stream timing before starting a writer. A failed thread start returns the same object before releasing the candidate. Once started, join the writer before destroying its Pipeline. Finalize closes I/O; release then frees audio references and callback storage exactly once.
- Never introduce a second output packet-writing path, an independent audio-registration path, or an interleaver behind another component's back. Keep original first-frame, successful-write latency, watermark delivery and PTS-ledger confirmation boundaries.
- Frame wire codecs serialize explicit bounded fields and must not include mutable Job/Pipeline state. `frame_trace.h` is local lineage data, not a raw wire representation. Do not change its propagation/retirement semantics while reorganizing code.
- Lifecycle changes must state which owner advances the transition, what remains owned on failure, how cancellation wakes progress, and what proves a resource can be reclaimed. Extend deterministic contract tests first; retain the relevant real-media integration coverage.
- Rendition membership, handshake, stop policy, sticky outcome and holder ownership change through `rendition_lifecycle.h` events, with strictly newer generations on restart. `NakiTopologyPhase` must advance through its checked transition API. Do not reintroduce `prepared/finished/failed/stopping/member/attached/restarting` flag combinations or access opaque lifecycle storage. A transport EOF checkpoint is distinct from terminal media and exit proof.
- Destination writer execution uses atomic `NakiWriterLife`; owner attachment uses `NakiDestinationLife`. Readiness, verified IDR admission, operation commit and actual successful flush remain separate. Failure/completion cannot be undone by a late ready event. `done` alone never authorizes ID/budget release: require successful native join and the joined event before reclamation. A failed join must fail closed.
- Run architecture/organization checks for dependency changes; `media-lifecycle` for lifecycle changes; `mux-lifetime` for output handoff; retain the matching real-media gate. Use `docs/architecture.md` to select scope rather than expanding every local change into the full benchmark matrix.
